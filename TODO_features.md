# TODO для BormoStats (Roadmap 2026)

> **Context for LLM / Инструкция для ИИ-ассистента:**
> Ты работаешь над проектом BormoStats. Это Self-Hosted аналитика для селлеров маркетплейсов (WB, Ozon).
> Стек: Python (FastAPI), ClickHouse (raw -> stg -> mrt), Celery (Background tasks), React 19, Telegram Bot (уведомления по YAML), Browser Extension (Chrome/FF).
> **Ключевое ограничение:** Бэкенд не использует прокси и не парсит маркетплейсы! Все внешние данные собираются либо через официальные API кабинета продавца, либо парсятся браузерным расширением на стороне клиента и отправляются на наш бэкенд через REST API.

## Phase 2: Критическая автоматизация (Bidder & Repricer)

*Фокус: Автономное управление рекламой и ценами через официальные API (Celery tasks).*

- [ ] **2.1. Биддер (Управление авторекламой WB/Ozon)**
  - **БД (PostgreSQL/SQLite в FastAPI):** Создать таблицы `AdCampaign`, `AdRule` (target_cpm, max_cpm, target_position).
  - **Celery Worker:** Написать периодическую задачу (каждые 3-5 мин), которая стягивает текущие ставки кампаний через API WB (миграция 0010 `Ad performance`), проверяет правила и делает POST-запрос на изменение ставки.
  - **UI:** React-интерфейс со списком кампаний и ползунками для настройки правил.
- [ ] **2.2. Репрайсер (Динамическое ценообразование)**
  - **БД:** Таблицы `PriceRule` (min_price, max_price, target_margin_percent).
  - **ClickHouse:** Написать SQL-вью в слое `mrt`, которая связывает текущую цену, себестоимость и комиссию (Unit Economics) для вычисления минимально допустимой цены (Break-even point).
  - **Celery Worker:** Мониторинг изменения цен конкурентов (через данные расширения) или акций МП. Если триггер сработал -> отправка новой цены по API. Обязательная валидация: `new_price >= min_price`.
