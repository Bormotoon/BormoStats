# Webhooks

Organizations subscribe HTTPS endpoints to events; BormoStats signs and delivers them
from the `webhooks` Celery queue with retries.

## Events

| Event | Emitted when |
|---|---|
| `insight.created` | the insights generator created new recommendation tasks |
| `stock.update.completed` | `POST /api/v1/integrations/stock/update` finished |
| `marketplace.action` | the bidder/repricer applied or failed a live change |
| `webhook.test` | `POST /api/v1/integrations/subscriptions/{id}/test` |
| `*` | all of the above |

## Delivery format

```http
POST /your/endpoint
Content-Type: application/json
X-BormoStats-Event: insight.created
X-BormoStats-Event-Id: 4d4c…            (also sent as Idempotency-Key)
X-BormoStats-Timestamp: 1790000000
X-BormoStats-Signature: v1=<hex HMAC-SHA256(secret, "<timestamp>.<raw body>")>

{"id": "4d4c…", "type": "insight.created", "organization_id": "…", "created_at": "…", "data": {…}}
```

## Verifying a delivery (receiver side)

1. Recompute `HMAC-SHA256(secret, timestamp + "." + raw_body)` and compare with the
   signature in constant time.
2. Reject timestamps older/newer than 5 minutes (replay protection).
3. De-duplicate by `X-BormoStats-Event-Id` — a delivery can be retried.
4. Answer 2xx quickly; process asynchronously.

Python reference: `common.webhooks.verify_signature(secret, timestamp, body, signature)`.

## Secrets

- The signing secret is generated by the server and returned **once** on create and on
  `POST …/rotate-secret`. It is stored encrypted (AES-256-GCM) under
  `WEBHOOK_SECRET_KEY`; the API never returns it again.
- Rotating `WEBHOOK_SECRET_KEY` makes stored secrets undecryptable: rotate every
  subscription secret afterwards (deliveries fail as `dead_letter` until then).
- Secrets stored in plaintext by older versions are cleared by migration `0024`;
  rotate those subscriptions.

## Retries and dead letters

Failed attempts (network errors, non-2xx) are retried with exponential backoff:
30 s, 1 min, 2 min, 4 min, 8 min — six attempts in total. After the last attempt the
delivery is logged as `dead_letter` and the `WebhookDeadLetters` alert fires.
Every attempt is visible in `GET /api/v1/integrations/logs` (status, HTTP code,
attempt, next retry).

## SSRF protection

Endpoint URLs must be `https://` and resolve only to public addresses; loopback,
private, link-local (cloud metadata), multicast and reserved ranges are rejected at
creation **and** re-checked on every attempt. The connection is pinned to the validated
IP (SNI/Host keep the original name) so DNS rebinding cannot redirect it, and
redirects are not followed. `WEBHOOK_ALLOW_PRIVATE_TARGETS=true` relaxes this for
local development only and is rejected in stage/prod.
