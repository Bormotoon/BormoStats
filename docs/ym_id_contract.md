# YM идентификаторы: контракт

Зафиксировано: 2026-11-02.

## Различия идентификаторов

| Идентификатор | Назначение | Формат/замечания |
| --- | --- | --- |
| `businessId` | Идентификатор кабинета (бизнеса) | Числовой/строковый по API; хранится как строка в конфиге/моделях. |
| `campaignId` | Идентификатор магазина/кампании | Соответствует модели работы (FBY/FBS/DBS/Express). Может быть несколько на бизнес. |
| `account_id` | Внутренний идентификатор аккаунта в системе | Используется для изоляции в БД/кешах. Для YM привязан к организации через `dim_account`. |
| `offerId` / `shopSku` | SKU продавца (артикул поставщика) | Строковый/цифровой артикул, может содержать буквы, дефисы, подчеркивания, ведущие нули. Не нормализуется в число. |
| `marketSku` | Идентификатор карточки товара в Маркете | Числовой идентификатор, может отсутствовать. Не используется для объединения разных предложений. |

## Правила работы

- Разные аккаунты с одинаковыми SKU не смешиваются (изоляция по `account_id`).
- Товары без `marketSku` остаются отдельными предложениями, не объединяются.
- При появлении `marketSku` у ранее импортированного предложения сохраняется история связей, исключаются дубли.
- Дедупликация и JOIN по SKU/orders/складам учитывают `account_id`.
- Ключи дедупликации не приводят строковые SKU к числовому типу без потери ведущих нулей.
