# Яндекс Маркет: состояние интеграции

План: [yandex_todo.md](../yandex_todo.md). Локальная реализация добавляет код `ym`, сбор каталога, заказов, остатков, цен, отзывов и отчётов, витрины, API, интерфейс и расширение. Значения `YM_ACCOUNT_ID` (если задан) и `YM_CAMPAIGN_ID` должны соответствовать магазину в `dim_account`. Один процесс коллектора обслуживает один настроенный магазин; общий для кабинета отчёт по бусту не записывается в магазин, если в кабинете несколько магазинов.

Проверены миграция и SQL на отдельном ClickHouse, парсеры на примерах контрактов API, интерфейс на локальных данных через Playwright. Внешний API с ключом продавца и реальные записи цен, ставок, остатков и ответов не проверялись. Подключение следует проверять сначала с `MARKETPLACE_ACTIONS_ENABLED=false` и отдельным тестовым кабинетом.

## Остаётся до полной готовности

- Режим остатков задаётся через `YM_STOCK_MODE`: `grouped` — v2 для FBY и групп складов; `partner` — v3 для партнёрских складов без групп. Выбор режима и привязку склада к магазину нужно проверить на конкретном кабинете.
- Данные заказов берутся из business orders. Комиссии и фактические скидки из `stats/orders`, прогноз тарифов и корректный учёт частичных возвратов ещё не подключены к витринам. Не следует считать показанные нулевые комиссии подтверждённым отсутствием расходов.
- Классификация финансов основана на названиях операций и услуг и требует сверки с настоящим отчётом продавца. Неизвестные операции попадают в `other`; проверка отчёта по бусту и воронке на реальных выгрузках также остаётся открытой.
- API не предоставляет аналог снимка баланса, поэтому `ym_balance_snapshot` возвращает `unsupported`; фиктивные значения баланса не создаются.
- Публичный сбор конкурентов основан на JSON-LD и зависит от выдачи страницы; CAPTCHA или изменение разметки приводит к ошибке задачи, а не к успешной пустой загрузке.
- URL страницы Маркета может содержать ID модели, а не marketSku. Расширение отправляет позиции только когда находит явный `sku`; его работу с текущей разметкой и авторизацией Маркета нужно проверить в установленном расширении.

Доступность данных за длительные периоды и частота генерации отчётов зависят от ограничений API и тарифа. Перед длительным backfill проверьте квоты кабинета.
