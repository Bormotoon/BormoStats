# Яндекс Маркет: состояние интеграции

Актуальная матрица работ: [yandex_market_parity_todo.md](yandex_market_parity_todo.md); доказательства реализации и результаты проверок: [yandex_market_implementation_report.md](yandex_market_implementation_report.md); матрица сценариев: [ym_scenario_matrix.md](ym_scenario_matrix.md).

Вся кодовая база, очереди Celery (`ym`), SQL-трансформации, витрины ClickHouse, архивация и очистка `raw_ym_*`, сервисы backend, UI-страницы, локализация и браузерное расширение приведены к паритету с Wildberries и Ozon и проверены модульными, воркерными и интеграционными тестами.

Для локального запуска или подключения магазина передайте `YM_API_KEY`, `YM_BUSINESS_ID`, `YM_CAMPAIGN_ID` и `YM_ACCOUNT_ID` в `.env` (список кампаний доступен через `GET /v2/campaigns`). Аккаунт с тем же `account_id`, который использует коллектор, необходимо привязать к организации через настройки приложения для доступа к данным в мультиарендных витринах.

## Особенности источника и оставшиеся шаги приёмки на реальном кабинете

- **Режим остатков (`YM_STOCK_MODE`)**: `grouped` (витринные остатки без привязки к конкретному складу партнёра) и `partner` (остатки по явному `partnerWarehouseId` с проверкой принадлежности магазину). Перед включением записи на боевом кабинете проверьте используемую модель (`FBY`, `FBS`, `DBS`, `Express`).
- **Тарифы и удержания по заказам**: скидки и софинансирование из `stats/orders` сопоставляются с ценой продавца того же заказа (`1-sale`). Комиссии заказа распределяются на товар в однозначном случае одной позиции (`commissions_exact = 1`); для многотоварных заказов сохраняются на уровне заказа, а в `mrt_price_current` при отсутствии точных комиссий используется тарифная квота (`raw_ym_tariff_quotes`).
- **Финансы и P&L**: классификация в `common/finance.py` и `mrt_finance_daily_ym.sql` синхронизирована; выплаты выделены в `payouts` и не занижают `net_accrued`; в `mrt_pnl_monthly.sql` исключено двойное списание расходов на «Буст продаж» между `united-netting` и `shows-boost`.
- **Возвраты и история доставок**: наблюдённые доставки сохраняются в `raw_ym_delivered_snapshots`; при первом импорте уже возвращённого заказа продажа восстанавливается из подтверждённых проводок `raw_ym_finance` (`recovered_from_finance`), а при отсутствии следов доставки в API помечается `return_without_observed_delivery` без генерации фиктивной продажи.
- **Снимок баланса**: Partner API не предоставляет отдельного эндпоинта текущего баланса счёта, аналогичного WB/Ozon, поэтому `ym_balance_snapshot` явно возвращает `unsupported` без создания фиктивных нулевых значений.
- **Контрольная сверка на живом кабинете**: перед включением `MARKETPLACE_ACTIONS_ENABLED=true` рекомендуется выполнить read-only сверку контрольного периода (заказы, продажи, возвраты, категории финансового отчёта и буст) на реальном кабинете продавца.
