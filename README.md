## 💡 Why BormoStats

Seller cabinets on Wildberries, Ozon, and Yandex Market each show a slice of the picture: one report for sales, another
for payouts and realization, a third for ads, and none of them reconcile unit economics across all three marketplaces.
Cloud analytics SaaS platforms solve that by asking for your API keys and storing your commercial data on their servers.

BormoStats is the **self-hosted alternative**. It pulls everything from the **official seller APIs** of your
own accounts into a ClickHouse warehouse on your machine and gives you a fast React 19 web UI, a REST API, BI
dashboards, and Telegram alerts — plus autonomous tools that act: a smart repricer that keeps the price the
buyer sees (while respecting Ozon's price index and promotion limits), an ad bidder, and AI-assisted replies to reviews.
Every marketplace write action uses a **two-phase commit ledger** (`pending` → `applied` → `confirmed` via read-after-write reconciliation),
starts in **dry-run**, and requires an explicit global switch (`MARKETPLACE_ACTIONS_ENABLED=true`) to go live.

### Project boundaries

- ✅ Collects data from **your own** seller accounts through the official Wildberries, Ozon, and Yandex Market APIs
- ✅ Fully self-hosted — nothing is sent to third parties (optional AI features call the OpenAI-compatible endpoint *you* configure; fonts and assets are served locally)
- ✅ Optional competitor tracking covers only the SKUs and search keywords you list explicitly
- ❌ No marketplace-wide catalog scraping, no proxy farms, no market-share harvesting

## 🚀 Quick start

**You need:** Docker with Compose v2, `make`, and API tokens of a Wildberries, Ozon, and/or Yandex Market seller account.

```bash
git clone https://github.com/Bormotoon/BormoStats.git
cd BormoStats
make init ENV=dev        # or ENV=stage / ENV=prod
```

`make init` copies `.env.<env>.example` to `.env` and fills every secret (ClickHouse, Redis, admin key,
webhook and metrics tokens) with strong random values. Add your marketplace tokens to `.env`:

| Variable | Where to get it |
|---|---|
| `WB_TOKEN_STATISTICS`, `WB_TOKEN_ANALYTICS` | WB seller portal → Settings → API access (“Statistics”, “Analytics”) |
| `OZON_CLIENT_ID`, `OZON_API_KEY` | Ozon Seller → Settings → API keys |
| `OZON_PERF_CLIENT_ID`, `OZON_PERF_CLIENT_SECRET` | Ozon ad cabinet → Settings → API *(optional, for ads & SKU ad reports)* |
| `YM_API_KEY`, `YM_BUSINESS_ID`, `YM_CAMPAIGN_ID` | Yandex Market Partner portal → Settings → API modules *(optional, for Yandex Market)* |

Then start the stack:

```bash
make up
```

| What | Where |
|---|---|
| 🖥️ Web UI | <https://localhost:18443/ui/> *(self-signed certificate)* |
| ❤️ Health check | `curl -k https://localhost:18443/health/live` |
| 📈 Metabase | <http://localhost:13000> *(loopback only)* |

> [!TIP]
> The first build takes 3–5 minutes; later builds reuse the Docker layer cache. Data starts flowing on the
> next scheduler tick — use **Admin → Backfill** (or `POST /api/v1/admin/backfill`) to load history right away.

<details>
<summary><b>Run without Docker (bare metal)</b></summary>

Requires **Python 3.14+**, **Node.js 22+**, **ClickHouse**, and **Redis** on the host.

```bash

# (clear REDIS_USERNAME if your Redis has no ACL user)
```

## 🧩 Architecture

```mermaid
flowchart LR
    subgraph MP["Marketplaces"]
        WB["Wildberries API"]
        OZ["Ozon Seller + Performance API"]
        YM["Yandex Market Partner API"]
    end

    Beat["Celery Beat<br/>scheduler"] --> Worker
    MP -- "collect" --> Worker["Celery workers (wb · ozon · ym · etl)<br/>collectors · transforms · marts<br/>bidder · repricer · reviews"]
    Worker -. "bids, prices, stocks, replies<br/>(2-phase ledger, dry-run by default)" .-> MP
    Worker <--> Redis[("Redis 8<br/>broker · locks · query cache")]
    Worker --> CH[("ClickHouse 26.3 LTS<br/>raw → stg → mrt<br/>+ git-like history store")]
    CH --> API["FastAPI backend<br/>REST · unit economics · RBAC · audit"]
    API --> Nginx["Nginx<br/>TLS entry point"]
    Nginx --> UI["React 19 SPA<br/>/ui"]
    CH --> MB["Metabase"]
    Worker --> TG["Telegram alerts"]
    API --> WH["HMAC Webhooks"]
```

| Component | Technology | Role |
|---|---|---|
| **Backend** | FastAPI 0.135, Uvicorn, Python 3.14 | REST API, $O(N+S)$ SKU unit economics engine, RBAC, audit, health, metrics |
| **Workers** | Celery 5.6 | Collection (`wb`, `ozon`, `ym`), transforms, marts, automation, marketplace actions |
| **Scheduler** | Celery Beat | Periodic ingestion, catalog snapshots, action reconciliation, and maintenance |
| **Warehouse** | ClickHouse 26.3 LTS | OLAP storage (`raw_*` → `stg_*` → `mrt_*`) and append-only history store (`hist_*`) |
| **Broker & Cache** | Redis 8 | Celery broker, distributed locks, and tenant-scoped analytics query cache |
| **Frontend** | React 19, Vite 8, Tailwind CSS 4, Recharts | Single-page web UI served under `/ui` with local fonts and `.xlsx` engine |
| **Proxy** | Nginx 1.31 | The only public entry point, TLS termination, CSP and caching |
| **BI** | Metabase | Ad-hoc SQL and custom dashboards under a read-only ClickHouse user |

**Data flow.** Collectors write raw API responses with normalized keys to `raw_*` tables (idempotent
re-ingestion) and commit versioned snapshots to `hist_*`. Transforms build a unified cross-marketplace model
in `stg_*` and `dim_product`, and marts (`mrt_*`) hold the aggregates that the API and dashboards read.
Watermarks in `sys_watermarks` make collection incremental, `sys_task_runs` audits every run, and
`sys_marketplace_actions` tracks every external write (`pending` → `applied`/`failed` → `confirmed`).
See [docs/architecture.md](docs/architecture.md) and [docs/data_catalog.md](docs/data_catalog.md).

## 📡 API

Every endpoint lives under `/api/v1` and requires an `X-API-Key` header (or a session token from `POST /api/v1/auth/login`).
The OpenAPI contract is served to authenticated callers at `/api/v1/openapi.json`.

- **User keys** (`bsk_<id>_<secret>`) are shown once and stored as salted `scrypt` hashes. The organization
  and role (`owner`, `admin`, `manager`, `analyst`, `viewer`) come from the key — a request can never pick another tenant.
  Keys expire, rotate, and revoke; password changes immediately revoke active sessions and purge cached credentials.
- **Platform master key** (`ADMIN_API_KEY`) is for operators only: admin operations and cross-tenant work
  via `X-Organization-Id`. Restrict it to your networks with `ADMIN_ALLOWED_NETWORKS`.

```bash
curl -k -H "X-API-Key: $BORMOSTATS_KEY" \
  "https://localhost:18443/api/v1/sales/daily?marketplace=wb&date_from=2026-10-01&date_to=2026-10-31"
```

## 🛡️ Security

- **Hardened runtime**: containers run as a non-root user with read-only file systems, `no-new-privileges`, and `tmpfs` for `/tmp`.
- **Network isolation**: Nginx is the only public entry point; ClickHouse, Redis, Metabase, and metrics stay on internal Docker networks or host loopback.
- **Least privilege DB access**: the application uses a dedicated ClickHouse user (`analytics_app`), never the bootstrap admin.
- **Defensive HTTP & input sanitization**: strict `Content-Security-Policy`, `HSTS`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `.xlsx` zip-bomb and XML buffer-overflow guards, CSV spreadsheet formula-injection neutralization, SQL loader path-traversal bounds verification, and UI image URL protocol whitelisting.
- **RBAC & session security**: `scrypt`-hashed keys, instant session revocation and auth cache invalidation on credential or membership changes, and strict `ManagerAuth` protection on COGS and financial endpoints.
- **Supply chain**: dependencies are hash-locked (`requirements*.txt`, `package-lock.json`), base images are pinned by SHA-256 digest, and CI runs `pip-audit`, `npm audit`, Grype, and SPDX SBOM generation on every push. See [security_audit_report.md](docs/security_audit_report.md) and [docs/supply_chain_security.md](docs/supply_chain_security.md).

Found a vulnerability? Please **don't** open a public issue — report it privately as described in
[SECURITY.md](SECURITY.md).

## 🧪 Development

```bash
python3 -m venv .venv && ./.venv/bin/pip install -r requirements-dev.txt
make init ENV=dev

make lint            # Ruff check
make format-check    # Ruff format check
make typecheck       # MyPy, strict mode (backend, workers, collectors, automation, warehouse, scripts, common)
make migrate-verify  # Verify ClickHouse migration manifest and rollback scripts (0001–0051)
make test            # pytest: 700+ unit, worker, and ClickHouse/Redis integration tests
make check-frontend  # npm ci + npm audit + production build of the web UI
cd frontend && npm test           # Frontend unit tests (node --test)
cd frontend && npm run test:e2e   # Playwright E2E smoke tests
```

CI runs all of the above plus Docker image builds, Prometheus alert-rule unit tests, browser-extension tests,
migration upgrade/rollback round-trip verification, and a supply-chain gate on every push.

**Regenerating the README screenshots** — no stack or keys needed; the API is mocked and the browser is
blocked from reaching anything but the local preview server:

```bash
cd frontend && npm run build && npm run screenshots   # → docs/screenshots/{en,ru}/*.png
```
